## Controlled mutation evidence

`node plans/2026-10-17-test-strategy/mutation-check.mjs before` aliased the real billing module to a temporary copy containing one deliberate change. Its signature manifest was replaced by a constant, discarding event ID, delivery ID and timestamp. The working production source was never edited. All 18 original billing tests still passed.

The old test signed its fixture with `buildMercadoPagoSignatureManifest`, then verified it through code that called the same builder. It therefore used the behavior under test to define the expected result. The replacement uses a literal manifest and a fixed HMAC independently computed from the [provider's documented format](https://www.mercadopago.com.ar/developers/en/docs/wallet-connect/notifications). Tampered event, request, timestamp, secret and missing headers are rejected.

Running the same temporary mutation after the rewrite fails the provider-notification case. Results are retained in `mutation-before.json` and `mutation-after.json`. The rerunnable script requires exactly that failed case and Vitest's test-failure exit code before reporting the mutation killed. An unrelated failure cannot satisfy that check.

The final independent review also found weak fetch/update transport assertions. The three retained API tests now observe URL, method, authorization, JSON content type and exact create/update payloads. Fetch additionally checks encoded identifiers and absence of a request body. All 26 billing cases pass against the unmodified production module.

## Conclusion

Most short tests in this slice protect real contracts. Deleting them would remove useful negative and edge cases without creating a single missing user journey. The weak cases were the self-derived oracle, passthrough assertions and inadequate error/output assertions. The larger missing layer is actual route enforcement, persistence, cross-tenant access and complete state transitions.
