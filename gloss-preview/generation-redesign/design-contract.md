# Full generation redesign, 2026-10-15

User explicitly requested a structural redesign, replacing the earlier composition-preserving requirement for this screen only. Production routes and other four previews stay unchanged. This is a local proposal using fictional data, not shipped behavior. Product OS and Journey03 were inspected read-only. No external board edits authorized.

Decision, based on Opus 5.5 design: one structured composer; no Documento/Formulario toggle and no editable A4 canvas. Compact context summary expands inline for obra/folder/template cards. Main layout `minmax(0,1fr) 320px`, 24px gap, at screen container >=1040px. Composer is one raised surface with hairline-separated Encabezado, Proveedor, Materiales, Condiciones. Right readiness rail owns totals, real completeness checklist, saved status, destination and Review/Save actions. Under1040px rail stacks and a final DOM-child sticky review bar keeps actions near the user. Under720px items become stacked editable rows. No arbitrary z-index, no high-frequency motion.

Review happens in a canonical Dialog styled as right-side sheet. Read-only business document, pending issues linking to editor, final generation action if valid, local HTML result awaiting review, exact destination navigation. Pending fields never lock out review; the action becomes Corregir N pendientes and returns to the correct field. Focus restores to opener; successful generation focuses result heading. Paper uses its own document typography; app chrome retains Gloss.

Parent owns generation.tsx, generation.module.css and generation-model.ts/review-contract.ts; no other writer changes them. Composer writer owns generation-composer.tsx/module.css only, named export DocumentComposer, props GenerationComposerProps. Review writer owns generation-rail.tsx/module.css and generation-review.tsx/module.css only, named exports ReadinessRail, MobileReviewBar, ReviewSheet, DocumentPaper. Exact props/types in model/review-contract, shared types ../contracts.ts. MobileReviewBar props {total:number,pending:number,onReview:()=>void,onSave:()=>void}. DocumentPaper props {draft:PreviewDraft,obraName:string,templateName:string}. Both are presentational; parent owns draft, attempted validation, save state, context disclosure, removed row snapshot, review stage and generated record.

Composer stable section IDs: gen-header, gen-supplier, gen-items, gen-conditions. Each input has data-generation-key matching model issue key, e.g supplier, code, row-r1-quantity. aria-invalid/describedby with visible errors. Add row returns new ID; composer focuses its description in rAF; Enter in last-row input adds and focuses a row, with preventDefault to avoid form submission. Parent handles undo and returns removedRow+onUndoRemove. All fields supplied from PreviewDraft, no data copies or side effects.

Canonical UI imports @/components/ui/*, Lucide icons. gp CSS vars body theme handles portals. Child modules may query named generation container or their own stable parent container; never query a self-contained element to style itself. Native Dialog behavior and manual onCloseAutoFocus prevent focus loss. Body max widths, table scroll own region, 390/820/1440 checks. No dependencies/API/auth/DB/storage/credentials/deploy/commits or nested agents.

Behavior: explicit draft ID, per-obra latest saved, then global latest for sidebar. Save clones snapshots through shared actions. Changing obra saves dirty prior draft first, then restores target. Parent editor key is route identity only, never latest dataset draft ID, to prevent first save/generation remounting and losing the result. Generate calls onGenerateDocument only after fresh validation; parent shared action already saves its clone and creates .html/generated record. Keep review warning visible in Documents. Copy/code identifiers remain stable, blank new drafts use a new UUID, monetary cents use local formatAmount. Shared data/fixtures/backend untouched.

Required proof: visually distinct layout; context/template choices; blank new draft; add/duplicate/remove/undo; keyboard add; totals/bonification; invalid focus + row error cleanup; read-only review; generation→warning result→exact folder; new first-save doesn't remount; default and per-obra saved recovery and A→B→A; 390/820/1440 no page overflow; focus/Escape and static standalone build. Scoped tsc/lint/build and independent review after stable implementation.
